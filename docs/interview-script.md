# Interview Script

## 30 秒介绍

《灵墟地牢》是一个 Vite + React + Phaser 的俯视角动作 Roguelite 网页试玩。当前公开版本聚焦第一关闭环：玩家选择武器，探索 6-8 房间随机路线，通过战斗、事件、奖励和遗物成长，最终挑战源晶核心；结算数据会保存到 localStorage，并在数据分析页形成规则诊断和可选 AI 报告。

## 1 分钟介绍

当前线上试玩只暴露三个入口：首页、游戏试玩、数据分析。首页说明试玩范围和推荐演示顺序；游戏试玩页承载第一关可玩流程，包括遗迹猎人、四种武器、战斗房、事件房、奖励三选一、遗物成长和 Boss 结算；数据分析页读取真实 GameRun，展示通关率、角色胜率、常见失败原因、首领剩余血量和最近 10 局。

AI Designer 与 Asset Forge 代码仍保留在项目内，用于内部开发和后续扩展，但当前线上试玩隐藏入口。没有 OpenAI API key 时，分析报告仍可用 mock / 规则 fallback，保证演示稳定。

## 3 分钟介绍

我把这个项目收敛成“试玩 -> 结算 -> 数据反馈”的第一关验证闭环，而不是一次性铺开多关卡和正式素材。这样做的好处是演示路径更稳定，也更容易围绕玩家体验持续迭代。

玩法侧，Game 用 Phaser 实现俯视角动作战斗。当前主角是遗迹猎人，支持短剑、重刃、长枪、双匕四种武器，关卡由 6-8 个房间组成，包含普通、高级、精英战斗房、事件节点和 Boss 房。战斗判定仍由游戏逻辑驱动，不依赖动画；美术资源以 generated SVG 和 Phaser Graphics fallback 为主，避免引入版权不明素材。

数据侧，每局结算会保存为 GameRun。Analytics 会读取 localStorage，做基础统计、失败原因归因、角色胜率和最近对局展示；如果 API 可用，可以生成 AI 分析报告，如果不可用，也能用 mock / 规则结果完成演示。

工程侧，当前重点不是堆功能，而是保证线上试玩口径清晰、异常数据不污染页面、空数据不出现 undefined / NaN、控制台不出现当前功能相关的新异常。实验分支中的小 commit 会先本地验证，再由人工决定是否整理进正式版本。

## 常见问题

Q：这个项目和普通小游戏有什么区别？

A：普通小游戏通常只展示玩法结果；这个项目同时展示可玩闭环、结算记录、数据分析和后续 AI 调优入口。它更像一个可持续迭代的玩法验证台。

Q：为什么当前线上试玩隐藏 AI Designer 和 Asset Forge？

A：当前公开试玩目标是让用户最快进入首页、游戏试玩和数据分析。Designer 和 Asset Forge 仍在代码里保留，适合内部开发和后续扩展，但公开入口先收敛，降低演示噪音。

Q：没有 OpenAI API key 会不会影响演示？

A：不会。当前试玩路径不依赖 API key；生成分析报告时也有 mock / 规则 fallback，可以稳定展示完整流程。

Q：为什么暂时不接正式角色 sprite 和武器挂载动画？

A：当前阶段优先保证玩法判定、结算数据和线上试玩稳定。正式素材需要授权、风格和资源清单都确认后再接入，而且动画不能驱动战斗判定。

Q：后续最值得继续做什么？

A：优先整理实验分支中稳定的小修补，继续提升结算页与数据分析页一致性、localStorage 脏数据兜底、试玩流程提示、控制台异常清理和项目文档质量。
