# V1.7 主角运行时资源管线

本文记录 V1.7.3 时《灵墟地牢》主角运行时资源的实际生成、加载和渲染路径，并为后续版本拆分接入步骤。本文只描述资源与视觉层，不调整战斗逻辑。

## 1. 当前主角资源现状

当前游戏内主角使用生成资源，而不是 `public/assets/game/characters/relic_hunter/` 下的正式角色模型。

- 生成脚本：`scripts/generate_hunter_assets.ts`
- npm 命令：`npm run generate:hunter`
- 运行时目录：`public/assets/generated/characters/hunter/`
- 资源格式：SVG
- 画布尺寸：每张 SVG 为 `96 x 96`
- 方向：`down`、`up`、`left`、`right`
- 每方向帧：idle、walk 1、walk 2
- 总数：4 方向 x 3 帧，共 12 张 SVG

现有文件命名如下：

```text
hunter_{direction}.svg
hunter_{direction}_1.svg
hunter_{direction}_2.svg
```

`public/assets/game/characters/relic_hunter/` 当前只有 README 和 `ui/` 图片。`sprites/` 目录尚不存在，也没有正式运行时主角 sprite。

## 2. 当前主角渲染流程

主要实现位于 `src/game/scenes/DungeonScene.ts`。

1. `preload()` 对四个方向分别注册 idle、walk 1、walk 2，并为每一帧同时尝试 PNG 和 SVG 路径。
2. 运行时 texture key 保持为：

```text
hunter-{direction}-png
hunter-{direction}-svg
hunter-{direction}-{1|2}-png
hunter-{direction}-{1|2}-svg
```

3. `hunterAssetKey()` 按 PNG、SVG、同方向 idle、`hunter` 的顺序选择可用纹理。
4. `createPlayer()` 使用 `hunterAssetKey('down')` 创建 Arcade Sprite。
5. 角色显示尺寸固定为 `HUNTER_DISPLAY_SIZE = 51`，即 `51 x 51`。
6. Arcade Body 固定为 `30 x 30`，并在纹理切换后重新设置，以防贴图尺寸影响碰撞体。
7. 最终的 `hunter` 回退纹理由 `createHunterTexture()` 使用 Phaser Graphics 生成，原始尺寸为 `48 x 48`。

当前目录没有生成 PNG，因此加载器会先请求不存在的 PNG，再使用同名 SVG。后续正式资源接入后，应避免继续产生无意义的 PNG 加载失败日志。

## 3. 当前方向与移动表现

移动输入在 `movePlayer()` 中读取 WASD 和方向键，并归一化移动向量。

- 非零移动向量会写入 `lastFacing`，供武器、普攻和冲刺共同使用。
- `updatePlayerDirection()` 使用绝对轴值判断主方向。
- 水平分量绝对值大于垂直分量时使用 left/right，否则使用 up/down。
- 移动时每 160ms 在 walk 1 和 walk 2 之间切换。
- 停止移动时恢复当前方向 idle。
- 找到方向资源时角色旋转固定为 0。
- 只有退回通用 `hunter` 纹理时，才根据移动向量旋转该通用纹理。

移动速度不是动画参数。实际速度由玩家基础速度、武器移动倍率、遗物倍率和房间倍率相乘得出。替换模型时不能调整这条计算链。

## 4. 当前武器显示方式

游戏内手持武器不是贴图，也没有使用 `artManifest` 中的武器攻击 spritesheet。

`playerWeaponVisual` 是深度为 31 的 Phaser Graphics，`updatePlayerWeaponVisual()` 每帧根据 `lastFacing` 在角色旁重新绘制：

- 短剑：亮色剑身和源晶色护手线。
- 重刃：三角形宽刃、握柄和描边。
- 长枪：枪杆、枪尖三角形和描边。
- 双匕：角色两侧各绘制一把短刃。

四种武器的形状、长度和位置都来自 Graphics 坐标。V1.7.4 只替换角色 idle/walk 时，应继续保留这层 Graphics，避免把角色换图和武器手持适配混在同一版本。

## 5. 当前动作与反馈表现

### J 普攻

- `normalAttack()` 负责冷却、伤害和命中调用。
- 短剑、重刃和双匕使用 Phaser Arc 表现斩击。
- 长枪使用 Line 和 Circle 表现直线刺击。
- 重刃额外触发轻微镜头震动。
- 双匕视觉和命中分为两段。
- `artManifest` 中存在攻击动画配置，但当前没有实际播放这些动画。

### K 冲刺斩

- 角色使用 Tween 在 200ms 内移动到合法目标点。
- 冲刺期间复制角色当前纹理生成四段淡出残影。
- `dashLine` 使用当前武器颜色、并按武器类型设置线宽。
- 命中范围、伤害、击退和冷却独立于角色贴图，不能因视觉替换而调整。

### L 护盾

- 主护盾是跟随玩家的 Phaser Circle，包含填充、描边和循环缩放透明度动画。
- 启动时增加扩散圆环并给玩家加绿色 tint。
- 吸收时显示额外圆环、六个火花和浮动文字。
- 护盾容量、持续时间、冷却和吸收流程不依赖角色资源。

### 受击

- 显示伤害数字、红色圆形闪光和镜头震动。
- 较高伤害会增加全屏红色淡出层。
- 无敌帧期间角色闪烁并使用红色 tint。
- 当前没有播放 `hurt` 角色动画。

### 死亡

- `finishRun()` 停止玩家和敌人运动，清理战斗对象并显示结算面板。
- 失败时有全屏结束闪光和失败音效。
- 当前没有播放 `death` 角色动画，也没有切换死亡贴图。

## 6. 资源目录与 fallback 机制

### 当前生效目录

```text
scripts/generate_hunter_assets.ts
public/assets/generated/characters/hunter/
```

### 已接入 UI 目录

```text
public/assets/game/characters/relic_hunter/ui/
  relic_hunter_avatar.png
  relic_hunter_home_showcase.png
```

UI 图片只用于 React 页面，不参与 Phaser 内角色渲染。

### 预留正式资源目录

```text
public/assets/game/characters/relic_hunter/
public/assets/game/characters/relic_hunter/sprites/  # 当前不存在
```

### artManifest 状态

`src/game/assets/artManifest.ts` 预定义了 idle、walk、hurt、death 和武器攻击 spritesheet，但这些条目目前均为 `fallback: true`。`registerConfiguredArtAssets()` 会跳过这类条目，因此当前不会加载这些正式路径。对应动画 key 也只有在纹理确实存在时才会注册。

`DungeonScene` 中已经有查询 hero/weapon 动画 key 的包装方法，但当前没有代码调用 `player.play()` 或实际播放这些动画。这是一条预留管线，不是当前生效的角色渲染路径。

### 当前回退顺序

```text
同帧 PNG -> 同帧 SVG -> 同方向 idle -> Phaser 生成的 hunter 纹理
```

移动帧缺失不会让角色消失；会先退回同方向 idle。方向 idle 也缺失时，才使用通用 `hunter`。

## 7. V1.7.4 最小接入方案

V1.7.4 只接入四方向 idle/walk，建议继续使用“每帧独立图片”方案，不在同一版本切换到 spritesheet 动画系统。

1. 新建 `public/assets/game/characters/relic_hunter/sprites/`。
2. 提供 12 张透明背景正式 PNG：4 方向，每方向 idle、walk 1、walk 2。
3. 推荐统一命名：

```text
relic_hunter_{direction}_idle.png
relic_hunter_{direction}_walk_1.png
relic_hunter_{direction}_walk_2.png
```

4. 保持每张图相同画布、脚底锚点、主体比例和透明边距。
5. 在 `DungeonScene.preload()` 中把现有 `hunter-...-png` key 指向正式目录。
6. 保留现有 texture key、`hunterAssetKey()`、方向判断、160ms 步态切换和 idle 回落逻辑。
7. 保留 SVG 生成资源作为后备加载路径，直到正式 PNG 通过完整冒烟测试。
8. 保持 `HUNTER_DISPLAY_SIZE = 51` 和 Arcade Body `30 x 30` 不变。
9. 不接入 hurt/death/attack spritesheet，不修改 `artManifest` 动画播放链。

这样最小改动只发生在资源文件和 preload 路径，移动、朝向、碰撞和战斗逻辑保持原样。

## 8. V1.7.5 手持武器适配方案

V1.7.5 应在 V1.7.4 角色比例与脚底锚点稳定后单独处理。

- 继续使用 `playerWeaponVisual`，不要先改命中判定。
- 为四个方向分别校准手部偏移、武器起点和前向长度。
- 将纯视觉偏移整理为按方向、武器 ID 查询的常量表。
- 保持 `lastFacing` 为唯一战斗方向来源。
- 保持四种武器 ID、数值、攻击范围、攻击宽度、击退和冷却不变。
- 若未来改为武器贴图，先做到视觉等价，再考虑动画；不要让贴图尺寸参与命中计算。

## 9. V1.7.6 动作视觉增强方案

V1.7.6 再独立接入攻击、冲刺、护盾、受击和死亡视觉。

- 攻击：在现有命中调用之外播放角色或武器动画，不改变 `hitInArc()` 参数和调用时点。
- 冲刺：可替换残影材质或增加 dash trail 动画，但保留 Tween 时长、目标点和命中更新流程。
- 护盾：可替换圆环贴图和破碎效果，但保留容量、持续时间、冷却与吸收顺序。
- 受击：可播放 hurt 动画，但必须与无敌帧闪烁和 tint 兼容。
- 死亡：可在结算面板出现前播放短 death 动画，但不能改变结算记录或游戏结束条件。
- `artManifest` 的 spritesheet 和 animation key 可在该阶段逐项启用，每项都必须保留当前 Graphics 视觉作为回退。

## 10. 必须保持不变的内容

以下内容属于玩法和手感边界，资源接入不得顺带修改：

- 玩家碰撞体：`30 x 30`
- 玩家显示尺寸基准：当前 `51 x 51`
- 玩家基础速度和全部速度倍率计算
- J 普攻判定、冷却、伤害、范围、宽度、击退和双匕两段时序
- K 冲刺斩距离、200ms Tween、命中半径、伤害、击退和冷却
- L 护盾容量、持续时间、冷却、吸收顺序和结束条件
- 四种武器数值和武器 ID
- 武器选择流程
- 怪物逻辑
- 房间和路线逻辑
- Boss 逻辑
- 奖励与事件逻辑

2. 四个方向移动时都在 walk 1 / walk 2 间正常切换。
3. 停止移动后恢复最后朝向的 idle。
4. 对角移动的主方向选择与当前版本一致。
5. 角色显示尺寸与脚底位置稳定，无明显跳帧或漂移。
6. 玩家碰撞体仍为 `30 x 30`。
7. 玩家速度、房间边界和墙体碰撞体感不变。

10. K 冲刺残影使用当前正式角色帧且不出现空白纹理。

14. typecheck、build 和浏览器冒烟全部通过。

## 12. 风险点与回退方案

### 风险点

- 正式 PNG 透明边距不同会造成角色视觉抖动或武器悬空。
- 各方向脚底锚点不一致会让角色看起来在地面上滑动。
- 替换显示尺寸可能间接改变玩家对距离和碰撞的判断。
- 改用 spritesheet 会扩大代码改动范围，并引入动画 key、帧尺寸和播放状态问题。
- 攻击或受击动画若抢占 idle/walk 状态，可能导致方向帧卡住。
- 删除生成 SVG 回退过早，会让单个资源加载失败直接退回通用几何纹理。
- 角色图若自带武器，会与 `playerWeaponVisual` 重叠。

### 回退方案

- V1.7.4 保留现有 generated SVG 和 `hunterAssetKey()` 回退链。
- 正式资源只替换 preload 的 PNG 路径，不删除旧资源或通用 `hunter` 纹理。
- 若正式资源出现问题，可将 PNG 路径恢复为当前 generated 路径，逻辑代码无需回滚。
- 每次只启用 idle/walk、武器、动作反馈中的一个层级，避免多个视觉系统同时变化。
- 回退时绝不调整碰撞体、速度、技能判定或武器配置来补偿视觉问题。
